**Evidence:**
- Collector health: all telemetry targets UP (only the always-idle `vllm-*` targets down — normal).
- 15-minute anomaly scan on `nccl_profiler_collective_bytes_total` shows all four ranks collapsing **in lockstep** starting at **11:38:01** — healthy rate ~78.9 MB/s per rank dropped to near-zero with only intermittent small bursts, on bravo and golf alike, across all 4 ranks simultaneously.

- A re-check of the current 2-minute window confirms full recovery: all ranks now at ratio 0.94–1.06 (uniform, healthy).

**What I ruled out:**
- *Clock clamp* — SM clocks stayed uniform across all GPUs the whole time; no single rank showed a fixed-value clamp.
- *Rank death / collector kill* — no rank ever fully froze (delta stuck at exactly 0 with collector down or job dead); instead all ranks showed the same intermittent, synchronized near-zero/low-rate pattern, which is the interconnect-degradation signature (uniform step-down across ranks, not a hard stop).
- *Single-rank/link fault* — an early 2-minute snapshot briefly looked like rank 1 (bravo) alone was degraded (0.29 ratio vs. peers), but that was window dilution from catching the tail of the recovery ramp, not a real per-rank asymmetry — the 15-minute view shows all ranks moved together.

**Bottom line:** the interconnect degraded cluster-wide for roughly 8–9 minutes (11:38–11:47), collapsing collective throughput on both nodes simultaneously while GPU clocks stayed healthy. It has since cleared — the cluster is currently running at normal throughput. As with all network-degradation cases here, the metrics can identify the fault type and window but can't localize it to a specific physical link or node.
